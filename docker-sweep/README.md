# docker-sweep

Two-phase Docker image upgrade audit for the thenairn.com stack. Deterministic facts first, model judgment second, adversarial verification on anything consequential.

## Why

A naive "spawn agents to research each image" sweep drifts badly:
- **Year drift** — agents return the right month/day with the wrong *year* on release dates, producing false urgency.
- **Doc misreading** — "MongoDB 8.0 is *also* supported" got read as "*requires* MongoDB 8.0", nearly triggering a non-rollbackable DB migration.
- **No running-version awareness** — agents guess the deployed version from image age instead of checking, so already-patched services get flagged urgent.

The fix: put every hard fact (running version, build date, latest release, advisories, EOL) into deterministic code with no hallucination surface, and let agents do *only* judgment — then verify the calls that matter.

## Usage

```bash
# Phase 1 — deterministic facts (needs docker + authenticated gh)
python3 collect.py                      # reads inventory.json -> writes facts.json

# Phase 2 — judgment + adversarial verify (a Claude Code Workflow; needs opt-in)
# From Claude Code:  Workflow({ scriptPath: ".../sweep.workflow.js",
#                               args: { factsPath: ".../facts.json", generated: "YYYY-MM-DD" } })
```

`collect.py` prints a console table sorted by exposure (crit/high advisories in the gap) so you get a useful answer even without running phase 2.

## Files

| File | Role |
|------|------|
| `inventory.json` | **The stack's memory.** container → GitHub repo, endoflife slug, live-version probe cmd, criticality, gotchas. Keep in sync with the `docker-compose.*.yml` files. |
| `collect.py` | Phase 1. Probes live host + GitHub API + endoflife.date. Zero LLM. |
| `sweep.workflow.js` | Phase 2. Judgment-only fan-out over the facts, adversarial verify, dependency-ordered plan. |
| `facts.json` | Generated by `collect.py`. Not committed (regenerate on demand). |

## Maintaining inventory.json

When a service is added, removed, or repointed in a compose file, update its entry here in the same change. Fields:

- `container` — the running container name (what `docker ps` shows).
- `image` — image ref as pinned in compose.
- `repo` — GitHub `owner/name` for releases + advisories. Omit if not on GitHub.
- `eol` — endoflife.date product slug (e.g. `mysql`, `postgresql`). For datastores.
- `probe` — shell cmd run *inside* the container to print its real version. Prefer this over image labels.
- `compose` — which compose file it lives in.
- `criticality` — high / medium / low; operator's blast-radius call.
- `pinned` — true if compose pins an explicit tag (so it never auto-updates — these are the ones that silently rot).
- `note` — anything a reviewer must know (compat quirks, ordering constraints, backup-restore concerns).
